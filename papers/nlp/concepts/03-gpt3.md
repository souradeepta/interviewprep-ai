# Language Models are Few-Shot Learners (GPT-3)

## Paper Overview

**Title:** Language Models are Few-Shot Learners

**Authors:** Tom B. Brown, Benjamin Mann, Nick Ryder, et al. (OpenAI)

**Published:** NeurIPS 2020 | [arXiv](https://arxiv.org/abs/2005.14165)

**Citation:** 40,000+ (sparked the "scaling era" of AI)

This paper showed that scaling language models to 175 billion parameters enables **few-shot learning**: solving tasks with just 1-10 examples in the prompt, without any fine-tuning. GPT-3 can translate, answer questions, write code, generate creative text—all from a few examples in the prompt. This paradigm shift from "train on task-specific data" to "prompt with examples" fundamentally changed how we build NLP systems. No more fine-tuning pipelines; instead, you prompt-engineer. The implications: (1) language models become general-purpose reasoning engines, (2) scale becomes the dominant variable (bigger models solve more tasks), (3) in-context learning emerges as a core capability. GPT-3 didn't invent large models, but it demonstrated their power at scale and sparked the race to billion-parameter models (GPT-3.5, Gemini, Claude, etc.).

**Why this matters for interviews:** You need to understand few-shot learning, in-context learning, prompt engineering, and scaling laws. GPT-3 is the inflection point in modern AI. Questions like "How do you build a system for task X?" often assume GPT-3-style few-shot learning.

---

## Core Contribution

### The Problem: Fine-tuning Requirements

Pre-GPT-3, every task required:
1. Labeled training data (1K-1M examples)
2. Task-specific fine-tuning (hours-days)
3. Fine-tuned model deployment

This is costly, inflexible, and doesn't work for new domains where labeled data is scarce.

### The Solution: Few-Shot Prompting at Scale

GPT-3 (175B parameters) shows: **with enough scale, language models learn in-context from examples in the prompt without fine-tuning**.

Example: Translate English to French
```
Prompt:
"Translate English to French:
hello -> bonjour
goodbye -> au revoir
house -> maison
water -> "

Output: "eau" (water in French)
```

**Why this works:**
- Massive scale (175B parameters) learns diverse patterns from 300B tokens
- In-context learning: model learns the task (translation) from examples without parameter updates
- No fine-tuning needed; examples in prompt guide behavior

### Key Innovation: Scaling Laws Evidence

GPT-3 provides empirical evidence:
- Model size (parameters): 10x bigger → ~100× more capable
- Prompt examples: 0-shot < 1-shot < few-shot on many tasks
- Larger models benefit more from few-shot examples

## Key Ideas & Algorithm

### Few-Shot Prompting

**Zero-shot:** No examples, just task description
```
Q: What is the capital of France?
A: Paris
```

**One-shot:** One example, then task
```
Q: What is the capital of Germany?
A: Berlin
Q: What is the capital of France?
A: Paris
```

**Few-shot:** Multiple examples
```
Q: What is the capital of Germany?
A: Berlin
Q: What is the capital of Spain?
A: Madrid
Q: What is the capital of France?
A: Paris
```

**Chain-of-thought (few-shot with reasoning):**
```
Q: If there are 3 cats and each has 4 legs, how many legs total?
A: Let me think. 3 cats, each with 4 legs. 3 * 4 = 12 legs total.
Q: If there are 5 dogs and each has 4 legs, how many legs total?
A: 5 dogs, each with 4 legs. 5 * 4 = 20 legs total.
```

### In-Context Learning Mechanism

How does a language model learn from examples in the prompt?

1. **Pattern matching:** Model recognizes example format (input → output)
2. **Attention:** Attends to relevant examples when generating new output
3. **Implicit learning:** Parameters don't change, but attention weights shift based on examples
4. **Generalization:** Model infers the task rule and applies to new inputs

This is fundamentally different from fine-tuning (parameter updates). GPT-3 learns purely from context.

## Architecture & Trade-offs

### Few-Shot vs. Fine-Tuning

| Aspect | Few-Shot | Fine-Tuning |
|--------|----------|------------|
| **Labeled data needed** | 1-10 examples | 1K-100K examples |
| **Time to deploy** | Seconds (prompt only) | Hours-days (training) |
| **Flexibility** | Change task by editing prompt | Need new fine-tune for each task |
| **Accuracy** | Good for general tasks | Better on task-specific data |
| **Cost** | API call (~0.002$/1K tokens) | Training compute (expensive) |

### Prompt Engineering Techniques

| Technique | Example | When to use |
|-----------|---------|------------|
| Simple prompt | "Classify: text" | Clear, unambiguous tasks |
| Few-shot | "Example1\nExample2\nNew" | Tasks with clear patterns |
| Chain-of-thought | "Let me think step-by-step..." | Reasoning, math, complex logic |
| Role-playing | "You are a helpful assistant..." | Dialogue, content generation |
| Format specification | "Output as JSON..." | Structured output needed |

### Scaling Laws Insights

Power law: Performance ∝ (Model Size)^0.07

- Doubling model size → ~5% performance improvement on average
- But effect varies by task: reasoning benefits more than simple classification
- In-context learning improves dramatically with scale (cubed relationship empirically)

## Interview Q&A

**Q: How does GPT-3 do few-shot learning without fine-tuning? What's the mechanism?**

A: GPT-3 doesn't update parameters; instead, examples in the prompt guide attention. The model recognizes the input-output pattern (e.g., "English → French translation") and implicitly learns the task from context. At test time, attention attends to relevant examples and extrapolates the pattern to new inputs. This is fundamentally different from fine-tuning (parameter updates). It works because: (1) 175B parameters store diverse patterns from 300B training tokens, (2) attention can use examples to steer behavior, (3) language models are good at pattern completion. Limitation: few-shot works for tasks similar to pre-training data. For very different tasks (specialized domains), fine-tuning still helps.

**Q: When would you use few-shot vs. fine-tuning?**

A: Use few-shot when: (1) you need quick iteration (no training), (2) task is similar to pre-training data, (3) you have <100 labeled examples, (4) cost is important (API cheaper than training). Use fine-tuning when: (1) you have 1K+ labeled examples, (2) task is very different from pre-training (e.g., domain-specific), (3) you need maximum accuracy, (4) you're deploying on-device (can't use API). In practice: try few-shot first (costs ~$10 for experimentation), then fine-tune if few-shot isn't good enough.

**Q: What's the difference between in-context learning and fine-tuning?**

A: Fine-tuning updates model parameters on task data. In-context learning doesn't update parameters—examples in the prompt guide behavior through attention. Fine-tuning is slow (requires training) but can achieve higher accuracy on the specific task. In-context is fast (just prompt) and flexible (change task by editing prompt). In-context learning is an emergent capability of scale: small models (125M) barely do it, 175B does it well. Why? More capacity allows model to learn implicit "learning" mechanism—it internally simulates a learner without explicit parameter updates.

**Q: What's chain-of-thought prompting? Why does it help?**

A: Chain-of-thought (CoT) prompting asks the model to "think step-by-step" before answering. Example: "How many legs? Let me think... each cat has 4 legs, 3 cats, so 3*4=12." This helps because: (1) breaks complex reasoning into steps, (2) allows model to correct mistakes mid-reasoning, (3) models are better at step-by-step than jump-to-answer. Empirically: 5-shot CoT (with reasoning steps) > 5-shot without CoT on reasoning tasks. Cost: CoT generates more tokens (slightly more expensive) but often worth it for accuracy.

**Q: How do you write good prompts for few-shot learning?**

A: (1) Show examples that cover diverse cases. (2) Use consistent formatting (input → output structure). (3) Include edge cases if task has them. (4) Chain-of-thought for reasoning tasks. (5) Specify output format (JSON, list, etc.) if needed. (6) Use clear task description in system prompt. Example: instead of "Classify sentiment", write "Classify the movie review as positive (1) or negative (0)." Avoid: vague examples, inconsistent formatting, too many examples (4-5 is often optimal, not 10+). A/B test: try different prompts and measure accuracy on validation set.

**Q: What are the limitations of few-shot learning with GPT-3?**

A: (1) Fails on tasks very different from pre-training data (e.g., math, logical reasoning)—fine-tuning helps but not always enough. (2) Limited context window (2K-4K tokens for GPT-3, higher now): can't include too many examples. (3) Sensitive to prompt formatting: small wording changes can affect output. (4) Hallucination: generates plausible but incorrect text (especially for factual questions). (5) Bias: trained on internet text, inherits its biases. Mitigation: combine few-shot + retrieval (RAG), fine-tune for specialized tasks, verify outputs.

## Best Practices

- **Example selection:** Choose examples that are diverse and representative of the task. Avoid cherry-picked examples that make the model look good on that specific case.

- **Prompt clarity:** Be explicit about task requirements. Instead of "Translate:", write "Translate English to Spanish. Output only the translated text, no explanation."

- **Few-shot count:** 3-5 examples usually optimal. Too few (1) → high variance. Too many (10+) → context bloat, sometimes hurts accuracy.

- **Chain-of-thought:** Use for reasoning, math, logic tasks. Simple few-shot often sufficient for classification.

- **Output format:** Specify format clearly. "Output JSON: {label: ..., confidence: ...}" is better than "Output result".

- **Cost management:** Few-shot via API is cheap per-call but adds up. Fine-tune once if you'll call 1000s of times.

- **Fallback strategy:** Combine few-shot + retrieval (RAG) for factual tasks. Combine few-shot + fine-tuning for maximum accuracy.

- **Evaluation:** Always evaluate on validation set. Few-shot performance can vary with example selection and prompt wording.

---

## Common Pitfalls

- **Mistake: Vague or inconsistent prompt examples.** If examples have different formats, model learns inconsistent pattern. Impact: output quality is unpredictable.
  → Fix: Use consistent formatting across all examples (input → output, same punctuation, etc.)

- **Mistake: Too many examples causing context truncation.** If context window is exceeded, model ignores early examples. Impact: performance degrades.
  → Fix: Monitor token count. For GPT-3, limit to 2K tokens total (examples + prompt + generation space).

- **Mistake: Prompt too similar to training data.** If prompt accidentally overlaps with GPT-3 training set, model might just memorize. Impact: good in-context but poor generalization.
  → Fix: Use novel examples or fine-tune on proprietary data.

- **Mistake: Expecting few-shot to work on out-of-distribution tasks.** Few-shot learns from examples, but if the task concept is absent from pre-training, it won't work. E.g., very specialized domain (niche code library, domain-specific language).
  → Fix: Fine-tune on domain data first, then few-shot on top of fine-tuned model (called "meta-learning").

- **Mistake: Not handling hallucination.** GPT-3 generates confident-sounding but often incorrect facts. Impact: deployed system gives wrong information.
  → Fix: For factual tasks, combine with retrieval (RAG). For tasks where accuracy matters, validate or use fine-tuned model.

## Code Examples

### Example 1: Few-Shot Prompting with OpenAI API

```python
import openai

# Set API key
openai.api_key = "your-api-key"

# Few-shot prompting for sentiment classification
prompt = """Classify the sentiment of the movie review as positive or negative.

Review: This movie is amazing! I loved every minute of it.
Sentiment: positive

Review: Terrible film, waste of time.
Sentiment: negative

Review: It was okay, nothing special but not bad either.
Sentiment: neutral

Review: I couldn't stop laughing. Best comedy ever!
Sentiment: """

# Call GPT-3
response = openai.Completion.create(
    model="text-davinci-003",
    prompt=prompt,
    max_tokens=10,
    temperature=0,  # Deterministic for classification
)

print(response.choices[0].text.strip())  # "positive"
```

### Example 2: Chain-of-Thought Prompting

```python
prompt = """Solve step-by-step.

Q: If a rose costs $2 and I buy 3 roses, how much do I spend?
A: Each rose costs $2. I buy 3 roses. Total cost = 3 * $2 = $6.

Q: If a book costs $15 and I buy 2 books and a pen for $5, how much total?
A: Book cost = 2 * $15 = $30. Pen = $5. Total = $30 + $5 = $35.

Q: I have 5 apples. I give 2 to my friend and buy 3 more. How many do I have?
A: """

response = openai.Completion.create(
    model="text-davinci-003",
    prompt=prompt,
    max_tokens=100,
    temperature=0,
)

print(response.choices[0].text)
# "I start with 5 apples. I give away 2, so 5 - 2 = 3. I buy 3 more, so 3 + 3 = 6. I have 6 apples."
```

### Example 3: Few-Shot for Named Entity Recognition (NER)

```python
prompt = """Extract named entities (person, location, organization) from text.

Text: Apple Inc. was founded by Steve Jobs in Cupertino, California.
Entities: Apple Inc. (org), Steve Jobs (person), Cupertino (location), California (location)

Text: Elon Musk works at Tesla in San Francisco.
Entities: Elon Musk (person), Tesla (org), San Francisco (location)

Text: The meeting is with John Smith from Microsoft in New York.
Entities: """

response = openai.Completion.create(
    model="text-davinci-003",
    prompt=prompt,
    max_tokens=100,
)

print(response.choices[0].text)
# "John Smith (person), Microsoft (org), New York (location)"
```
